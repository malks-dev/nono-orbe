# 04 — Construindo a fundação do Nono Orbe

Depois de experimentar a interface, chegou o momento de construir a base que permitirá ao Nono Orbe deixar de ser apenas uma página visual.

A estrutura atual utiliza **PHP 8.3**, **Apache**, **MySQL 8.4** e **Docker Compose**.

Com o Docker Compose, a aplicação e o banco de dados podem ser iniciados juntos em um ambiente local. Isso facilita a instalação, os testes e a reprodução do projeto em outras máquinas.

![[docker-compose.png]]

## Um banco de dados com histórico

A nova base foi preparada para armazenar informações como perfis, preferências, categorias, atalhos, conversas, arquivos, recursos e solicitações.

Para construir e atualizar essa estrutura, o projeto utiliza **migrations**.

Cada migration representa uma etapa da evolução do banco de dados. Os arquivos são executados em ordem e registrados pelo sistema, permitindo identificar quais mudanças já foram aplicadas e quais ainda estão pendentes.

Em vez de reconstruir tudo a cada atualização, o Nono Orbe pode continuar exatamente do ponto em que parou.

A primeira sequência possui 11 migrations e cria 18 tabelas.

![[migrations.png]]

## E os seeds?

A pasta `seeds` também faz parte da estrutura, mas permanece sem arquivos SQL nesta primeira versão.

Isso é intencional.

Seeds são utilizados para inserir dados iniciais necessários ao funcionamento de um sistema. No Nono Orbe, eles ficarão reservados para futuros dados públicos e globais.

Uma instalação nova não deve trazer usuários, perfis, conversas, links ou informações pessoais preenchidas.

Categorias como Projetos, Financeiro, Contatos, Redes Sociais e Acessos serão criadas durante o primeiro acesso e pertencerão à organização de cada pessoa.

O sistema nasce vazio para que possa assumir a identidade de quem o utiliza.

## Documentação como parte do projeto

Os arquivos `README.md` estão sendo atualizados junto com o código.

Eles documentam as tecnologias utilizadas, a instalação, os comandos, a arquitetura, as migrations, as regras dos seeds e as decisões tomadas durante o desenvolvimento.

A proposta é que alguém consiga chegar ao repositório, compreender o estado atual do projeto e continuar a partir dali.

No futuro, também quero adicionar arquivos `AGENTS.md` em pontos estratégicos da estrutura.

Se o README funciona como um guia para pessoas, o AGENTS.md poderá orientar agentes de inteligência artificial sobre os padrões, responsabilidades e limites de cada parte do código.

Isso poderá facilitar a personalização do Nono Orbe por meio de **vibe coding**: a pessoa descreve o que deseja mudar e utiliza uma IA para ajudá-la a transformar essa intenção em código, respeitando a organização do projeto.

## A interface agora tem onde crescer

A página inicial continua sendo o ponto mais visível do Nono Orbe, mas agora existe uma fundação sendo construída por trás dela.

![[painel.png]]

Ainda faltam o primeiro acesso, a autenticação e a conexão da interface com as tabelas. Mesmo assim, o projeto já possui ambiente, banco de dados, histórico de atualizações e documentação.

O Nono Orbe começou como uma página local para reunir atalhos.

Agora começa a se transformar em um ambiente pessoal, aberto e programável para organizar informações, projetos e experiências digitais.
