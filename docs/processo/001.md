## Objetivo da primeira etapa técnica

A primeira etapa teve um objetivo pequeno e verificável: colocar no ar uma aplicação PHP simples, executada em Docker e acessível pela porta `9000`.

O resultado esperado foi uma página com `Hello, World!`. Essa primeira entrega estabelece a base sobre a qual serão adicionados interface, dados, autenticação, projetos e publicação por subdomínios.

## Organização inicial

O repositório foi separado por responsabilidade:

```text
orbe/
├── app/                     # Código da aplicação
│   └── public/              # Raiz pública do Apache
├── docker/                  # Infraestrutura versionada
│   └── php/
├── docs/                    # Documentação viva
│   ├── architecture/
│   ├── processo/
│   └── versions/
├── storage/                 # Dados gerados localmente
├── .env.example

```

Arquivos de código, configuração-modelo e documentação podem ser versionados. Credenciais, `.env`, vídeos, logs, uploads, sessões, cache, bancos e backups permanecem fora do Git.

## Aplicação PHP

O primeiro arquivo público foi criado em `app/public/index.php`. Ele identifica o sistema, a versão e confirma que o ambiente PHP está funcionando.

## Imagem PHP

A imagem do serviço foi definida em `docker/php/Dockerfile`:

```dockerfile
FROM php:8.3-apache

RUN a2enmod rewrite \
    && printf '%s\n' \
       'ServerTokens Prod' \
       'ServerSignature Off' \
       > /etc/apache2/conf-available/orbe-security.conf \
    && a2enconf orbe-security

WORKDIR /var/www/html

COPY app/public/ /var/www/html/

EXPOSE 80
```

A aplicação utiliza PHP 8.3 com Apache. O código de `app/public/` é copiado para `/var/www/html/`, a raiz pública dentro do contêiner.

## Orquestração com Docker Compose

O arquivo `compose.yaml` define o serviço `web`:

```yaml
name: nono-orbe

services:
  web:
    build:
      context: .
      dockerfile: docker/php/Dockerfile

    container_name: nono-orbe-web
    restart: unless-stopped

    ports:
      - "0.0.0.0:${ORBE_PORT:-9000}:80"

    volumes:
      - ./app/public:/var/www/html:ro

    healthcheck:
      test:
        - "CMD"
        - "php"
        - "-r"
        - "exit(@file_get_contents('http://localhost/') === false ? 1 : 0);"
      interval: 10s
      timeout: 3s
      retries: 3
      start_period: 5s
```

### Mapeamento da porta

```text
0.0.0.0 : 9000 : 80
   │        │      └── porta do Apache dentro do contêiner
   │        └───────── porta publicada no servidor
   └────────────────── interfaces de rede que aceitam a conexão
```

O endereço `0.0.0.0` permite acesso pelo próprio servidor e por outros dispositivos da mesma rede, desde que o firewall permita.

## Variável de ambiente

O `.env.example` registra a porta padrão:

```dotenv
ORBE_PORT=9000
```

Na instalação, o arquivo local é criado com:

```bash
cp .env.example .env
```

O `.env` real não é enviado ao GitHub.

## Construção e inicialização

Na raiz do projeto:

```bash
docker compose config
docker compose up -d --build
docker compose ps
```

O primeiro comando valida a configuração final. O segundo constrói a imagem e inicia o serviço. O terceiro mostra o estado do contêiner.

## Validação

### No próprio servidor

```bash
curl http://localhost:9000
```

### Em outro dispositivo da rede

Utilize o IP local do servidor:

```text
http://192.168.15.5:9000
```

### Porta publicada

```bash
docker port nono-orbe-web
```

Resultado esperado:

```text
80/tcp -> 0.0.0.0:9000
```

### Saúde do serviço

```bash
docker inspect --format='{{.State.Health.Status}}' nono-orbe-web
```

Resultado esperado: `healthy`.

### Registros

```bash
docker compose logs --tail=100 web
```

## Acesso pelo Cloudflared

O túnel pode encaminhar para o serviço local:

```yaml
service: http://localhost:9000
```

As credenciais e configurações autenticadas do Cloudflared permanecem somente no servidor.
