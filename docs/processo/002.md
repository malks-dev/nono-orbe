# Processo 002 — A fundação do Nono Orbe Core

Data: 28 de agosto de 2026
Versão: próxima versão em desenvolvimento
Estado: fundação do Core e dados implementada e validada localmente

## Contexto

O Nono Orbe começou como uma aplicação PHP simples executada em Docker.

A nova etapa estabelece uma fundação reutilizável para dois ambientes:

* Nono Orbe Local;
* Nono Orbe integrado ao WebFarm.

O objetivo é permitir que uma pessoa comece seu sistema em localhost e futuramente transporte informações autorizadas para uma instalação WebFarm.

## Separação de responsabilidades

A arquitetura foi dividida em três áreas de dados:

| Banco          | Responsabilidade                                              |
| -------------- | ------------------------------------------------------------- |
| `webfarm_core` | Identidade, autenticação, clientes e permissões               |
| `webfarm_crm`  | Projetos comerciais, tarefas, leads e cobranças               |
| `webfarm_orbe` | Perfil, preferências, comunicação e experiência personalizada |

O Nono Orbe é responsável por `webfarm_orbe`.

As informações de identidade são recebidas por meio do contrato:

```text
webfarm-core-identity/1.0
```

O Core reúne regras e componentes compartilhados.

Configurações específicas do ambiente Local ou WebFarm devem permanecer fora dele.

## Escolha do banco

O roadmap inicial previa PostgreSQL. Durante o planejamento da integração com o WebFarm, a decisão foi alterada para MySQL 8.4.

Motivos:

* o WebFarm já utiliza MySQL 8.4;
* as migrations podem ser compartilhadas sem tradução;
* o Nono Orbe Local e o WebFarm usam o mesmo comportamento SQL;
* a integração exige menos infraestrutura;
* o primeiro contrato de dados fica mais simples de validar.

A imagem utilizada é:

```text
mysql:8.4
```

A aplicação continua utilizando:

```text
php:8.3-apache
```

O driver `pdo_mysql` foi adicionado à imagem PHP.

## Ambiente Docker

O Compose passou a possuir dois serviços:

```text
web
mysql
```

Cada instalação recebe um slug:

```dotenv
ORBE_PROJECT_SLUG=local
```

Esse slug diferencia contêineres, redes e volumes de outras instalações existentes no mesmo computador.

O MySQL é publicado somente em:

```text
127.0.0.1:9001
```

A aplicação permanece disponível em:

```text
0.0.0.0:9000
```

## Segurança das configurações

O `.env.example` contém apenas nomes de variáveis e marcadores públicos.

O `.env` real:

* não é rastreado pelo Git;
* utiliza senhas diferentes para root e aplicação;
* não deve ser enviado ao repositório;
* não faz parte de exportações do usuário.

Volumes Docker também não fazem parte do Git.

## Contrato de identidade

O Nono Orbe não cria um tipo incompatível de usuário local.

Durante o primeiro acesso, o usuário local será representado como:

```text
usuário tipo cliente
→ cliente pessoal
→ vínculo administrador
→ perfil Nono Orbe
```

Relacionamentos entre bancos utilizam UUIDs.

IDs numéricos permanecem internos a cada banco.

## Exportação e importação

Foi preparada a base para uma exportação manual chamada `avatar`.

O pacote poderá transportar somente os dados autorizados do usuário, como:

* perfil;
* preferências;
* categorias;
* atalhos;
* recursos autorizados.

Senhas, tokens, sessões e credenciais não fazem parte da exportação.

Importações possuem registro de:

* manifesto;
* checksum;
* versão;
* instalação de origem;
* usuário de destino;
* conflitos.

O SQL recebido não deverá ser executado diretamente sem validação.

* registro em `schema_migrations`;
